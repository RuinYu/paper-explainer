# 五部分写作规范（单档 · 零基础）

这份文档定义每个部分必须包含什么、写到什么程度算合格。

**读者固定为一类人：对这个方向几乎没有基础，但理解力正常。** 不设 basic/pro 两档，不为“研究生读者”预留深度。遇到必须用到的专业词，就地解释；解释不了就换成白话，而不是加一句“详见某某教材”。

**总原则：篇幅由材料复杂度决定，不设硬性页数。**唯一硬指标是：该讲清的概念必须讲清，该列的术语必须列全。宁可多写两页，不要为了“精简”把因果链砍断。但“写得多”不等于“写得深”——篇幅应花在把一件事说透，而不是叠加术语。

---

## 六条贯穿全书的表达纪律

1. **先白话，后定义。** 每个概念先给一句大白话（外行也能点头），再给一句规范定义（能拿去引用）。两句话都要有，缺一句都不合格。
2. **句子短，从句少。** 一句话只讲一件事。出现“由于……从而使得……”这种三重嵌套，一律拆成两句。
3. **专业感来自准确，不来自术语密度。** 用词要准（该说“模场”就不说“光斑”），但不靠堆缩写制造难度。判断标准：一个聪明的大三学生读完能复述，且复述时不丢关键限定条件。
4. **每个形容词都要有落点。** “显著降低”“大幅提升”后面必须跟数字或条件；跟不出就删掉形容词，只留事实。
5. **语气不高于证据。** 论文写“可能”就写“可能”，写“约 1 dB”就写“约 1 dB”；两件事先后出现，不写成“因此导致”。
6. **不写稿子自身。** 不预告（“接下来我们看”）、不复述小标题、不总结自己刚写完的段落、不替读者宣布“你已经掌握了”。读者要的是内容，不是编排说明。

第 4–6 条与 `voice.md` 的四类文风病灶同源，写不顺时回那一页找判据。

## 第一部分：这个方向在干什么

**目标**：读完这一部分，读者能向别人解释“这批论文为什么值得做”。

必须回答四件事，缺一不可：

1. **研究对象是什么**——不是“研究 A 器件”，而是“A 器件在系统里承担什么功能”。用“它是××系统里的××环节”来定位。
2. **要解决的现实问题**——具体到“差几倍”“几个 dB”“几微米”，给数量级。
3. **不解决会怎样**——把后果翻译成系统指标：预算被吃掉多少、封装成本差几倍、良率管控是否失效、带宽被卡在多少通道。
4. **一个生活化类比**——必须给，并且必须写出**类比的边界**（在哪里不成立）。只给类比不划边界，读者会带着错直觉往后读。

**禁止**：在这一部分出现未解释的术语。如果非用不可，就地用一句话解释，或换成白话。

**合格判据**：把这部分单独发给一个外行，他能复述出“这个方向在跟什么东西较劲”。

## 第二部分：重要术语解释清单

**目标**：读完这一部分，读者能看懂论文标题和摘要里的每个词。

### 一词一条，绝不合并

**每个词条只讲一个术语。** 标题里不允许出现“A 与 B”“A vs B”“A／B”这类合并写法。

两个词容易混淆时，处理方式是：

- 各自独立成条，各写各的定义与应用场景
- 在各自条目之后用一句话点明区别（“注意：它和 ×× 不是一回事，区别在于……”）
- **不要**为了对比方便把两者塞进同一条，那会让读者以为它们是一个概念的两种叫法

同理，缩写与全称、中文名与英文名属于同一个术语，合在标题里（中文名 + 英文名），这不算合并两个术语。

### 每条两个字段

| 字段 | 写什么 | 常见错误 |
|---|---|---|
| 名字 | 中文名 + 英文全称 + 常用缩写 | 只写中文，读者对不上英文论文 |
| 概念 | 百科式的通行定义：先说它是什么，再说它由什么决定 | 只给一句比喻；或只给严格定义，等于没解释 |
| 应用场景 | 它在什么场合被使用、用来衡量或解决什么；在论文里出现在哪一步 | 写成“很重要”“用途广泛”这种空话 |

**没有公式字段。** 术语表不写公式。若某个术语离开数量关系就说不清，用一句文字说明“它大致与什么成正比、与什么成反比”，不摆符号式子。

### 概念与场景的写法：百科体

“概念”和“应用场景”两栏，参照专业百科（维基百科、百度百科、学科百科）的词条写法：

- **定义先行**：第一句就是“××是指……”，不铺垫、不设问、不讲故事
- **客观中性**：不写“非常关键”“极其重要”，重要性由事实体现
- **要素齐全**：是什么 → 由什么决定 → 用来做什么，三样至少占两样
- **不夹带个人判断**：这一栏只放学界通行说法；自己的推断放到正文里，并写明“这是推断”

**注意两条边界**：

1. 百科词条是通行定义，**论文可能有自己的用法**。若两者不一致，以论文为准，并在条目里补一句“本文中特指……”。
2. 不要照抄百科原文。用百科的**写法**（结构、语气、信息密度），不用它的**字句**。

### 排序与数量

按“读论文时会遇到的先后顺序”，不按字母序、不按拼音序。判据是——如果读者不懂 A 就看不懂 B 的定义，那 A 必须排在 B 前面。

数量宁缺毋滥，但“该列的必须列全”。判据是**覆盖率**而不是条数——论文摘要里出现的专业名词，凡是读者可能卡住的，都要有。

### 术语之间要显式写出关系

孤立词条等于词典，串起来才是知识。例如“A 是 B 的输入”“A 变大必然导致 B 变小”。关系写在“应用场景”一栏里，不另开字段。

## 第三部分：论文阅读顺序与理由

**目标**：读者能自己排阅读计划。

必须给一张表：序号 | 论文 | 精读/泛读 | 一句话理由。

排序原则（按优先级）：

1. **先单层后多层**——结构复杂度递增，认知负荷才可控
2. **先实测后仿真**——先建立“真实世界有多难”的判断力，再看待仿真值，不容易被骗
3. **先简单机制后复杂机制**——倒锥 → 多层绝热 → 超表面/拓扑优化，是一次次范式跃迁
4. **数据最全的放前面**——第一篇的作用是教会读者“怎么读损耗数据”，所以选实测项最完整的那篇，而不是最经典的

**必须说明为什么这样排**，不能只列表。要写出“先读 A 再读 B 会省力，因为 B 的某个概念在 A 里已经用具体数字建立过直觉”。

**必须区分精读与泛读**，并给出判据：什么情况下泛读够用（例如纯仿真且指标不占优、机制与已读重复）。

## 第四部分：逐篇精读引导

**目标**：每篇五个问题，形成统一档案，便于横向比较。

每篇固定五节：

1. **它回答的问题**——一句话，必须具体到物理量或工艺限制，不能写“提高耦合效率”。
2. **前人卡在哪里**——必须说清卡在哪个物理机制或工艺约束上。区分三类困境：真技术瓶颈、工程限制、作者自选的优化目标。
3. **它的关键做法**——拆成 **输入 → 处理 → 输出** 三步。禁用未解释术语。三步要能串成一句因果句。
4. **结果与代价**——效果提升什么（带口径、带测试条件），牺牲什么（尺寸、工艺步数、带宽、偏振、容差、可制造性）。**代价不能省略**，没有代价的方案不存在。
5. **与前面论文的关系**——改进了谁、留下什么坑。无直接引用证据时，只能写“技术路线相似”，不能写“继承了”。

每篇还必须加：

- **一张图**（结构剖面／光路分段／模场演化／技术路线，按内容选）
- **一句口径说明**（这篇的损耗怎么算的、能不能与别篇比较），用“注意”起头的普通段落，不做提示框
- **一条因果链**（起点约束 → 机制选择 → 结构要求 → 代价），编号列表

---

## 第五部分：总结

**目标**：把散点串成线——让读者合上书之后，脑子里剩下的是因果结构，不是一串数字。

**故事线**：一段连续文字，不分点。要求起点是一个物理约束，终点是仍未解决的问题，中间每一环都能说出“因为……所以……”。禁止写成“首先…其次…最后…”的伪叙事，也禁止在这一段里复述第四部分已经逐篇写过的结论。

**全书因果链**：这一部分末尾的那条链要跨越整批论文，不是任何单篇的复述。四环：共同约束 → 第一条路线为何不够 → 后续各自换掉了哪个自由度 → 至今未解的是什么。

不设自测题。检验读者是否读懂，靠的是因果链本身——链条断了，说明前面某一环没写透，回去补那一环，而不是加三道题。

## 全局写作规则

**唯一的硬约束清单在 `SKILL.md` 第 4 步**（内容八条 + 文风八条），本文件不重复，避免两处改一处漏一处。这里只补三条与结构强相关、别处没写的：

1. **首次出现的缩写必须展开**，格式：中文名（English Full Name, ABBR）。只在本部分出现一次的概念，也在出现处展开，不指望读者记得前文。
2. **术语一致性**——同一概念全书只用一种译法，首次出现时给出英文，之后不再换词。改写旧段时也要回头对齐，不能新旧两种译法并存。
3. **不写公式**——全书不出现公式。术语表尤其不设公式栏；必须表达数量关系时，用文字或具体数字例子（“模场差 5 倍，重叠效率就掉到几成”）。

## 常见失败模式

| 症状 | 病因 | 修法 |
|---|---|---|
| 读起来像论文摘要拼接 | 第四部分只是复述，没有拆解因果 | 强制每篇写“前人卡在哪”和“代价是什么” |
| 术语表很长但没用 | 按字母序排、把两个词并成一条 | 按认知顺序重排，一词一条，每条必须写它在论文哪一步出现 |
| 第一部分看不懂 | 用了未解释术语 | 逐个替换成白话，或就地加括号解释 |
| 读起来像百科复制粘贴 | 只抄定义，没落到这篇论文 | 定义之后必须补“本文中特指……” |
| 数字互相打架 | 混了口径、混了实测仿真 | 每个数字标注口径与数据性质，见 pitfalls.md |
| 因果链写成要点罗列 | 每一环之间没有“所以” | 每环必须以因果连接词开头，读一遍看能否连成一句 |
| 读起来像宣传稿 | 形容词多于数字，只讲好处不讲条件 | 删形容词，补数字与条件；每篇必写代价 |
| 读起来像模板生成 | 段段三项式、句句同头、破折号连用、句尾拔高 | 按 `voice.md` 三类改：列举项按实际数量、合并同头句、一段破折号不超过一次、删拔高尾句 |
| 段落开头总在说“本节” | 编排痕迹外露，读者被反复提醒自己在读书 | 段首直接给事实，不复述小标题 |
| PDF 目录页码错位 | 只渲染一次就写死页码 | 用 build_pdf.py 的多轮收敛 |
