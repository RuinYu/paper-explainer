# 版式规范（parchment 设计语言）

本 skill 的 PDF 视觉参考 kami 设计系统。**改模板之前先读这一页**，否则很容易退回"彩色提示框 + 装饰竖线"的默认审美。

一句话概括：**暖羊皮纸底、单一墨蓝强调、衬线承担层级、只用暖灰、靠留白分层，不靠色块和线条。**

---

## 一、十条不变量

每条都有实际代价，改之前先想清楚：

1. 页面底色固定羊皮纸 `#f5f4ed`，**不用纯白**，不用任何冷灰
2. 只有一个彩色强调色：墨蓝 `#1B365D`，占版面 **≤5%**，只用在页码、编号、关键术语
3. 所有灰色必须**暖调**（黄褐底色）。判据：`R ≈ G > B`。冷灰是 `R < G < B` 或三者相等
4. 全篇**一种衬线体**，不加第二种无衬线（除非是真 UI 元素）
5. 正文 400、标题换中宋。**不用合成粗体**（600/700），不加字重档
6. 行高：标题 1.15–1.30，正文 1.55，表格/图注 1.45
7. 字距：中文正文 `0.3pt`，英文正文 0；只有短标签和大写眉标才加宽
8. 容器背景用**实色 hex**，不用 `rgba`
9. 表面默认**扁平**，不用阴影
10. **不用斜体**。公式符号也用正体

## 二、色板

```css
/* 表面：由亮到暗，全部暖调 */
--parchment:#f5f4ed;      /* 页面底色 */
--ivory:#faf9f5;          /* 静默容器（定义框） */
--warm-sand:#e8e6dc;      /* 次级容器（论文框） */
--brand-tint:#eef2f7;     /* 墨蓝最浅填充（原理框） */
--tag-bg:#e4ecf5;         /* 标签填充 */
--warm-sand:#e8e6dc;      /* 次级容器（本 skill 已不用底色块，留作备用） */

/* 文字：四级，够用，不要第五级 */
--near-black:#141413;     /* 正文 */
--dark-warm:#3d3d3a;      /* 次级、表头 */
--olive:#504e49;          /* 导语、说明 */
--stone:#6b6a64;          /* 图注、页脚、元信息 */

/* 强调 */
--brand:#1B365D;
--brand-light:#2D5A8A;
--breaking-fg:#8b4513;    /* 警示标签文字 */

/* 分隔 */
--border:#e8e6dc;
--border-soft:#e5e3d8;
```

**"单一强调色"只有一个获批例外**：`--breaking-fg:#8b4513`，且**只用于「注意」两个字**的文字色。它不做底色、不做边框、不用于其他任何元素。**不要再加第二个语义色**——想加先改这一节。

**禁止**：纯白 `#ffffff` 作底色、`#f8f9fa`/`#f3f4f6` 这类冷灰、任何第二种彩色强调（绿/紫/青）。

## 三、字体（本机适配，务必照抄）

```css
--serif:"STSong","SimSun","Songti SC",Georgia,serif;       /* 正文 400 */
--serif-med:"STZhongsong","STSong","SimSun","Songti SC",Georgia,serif;  /* 标题 */
--sans:var(--serif);                                        /* 单衬线原则 */
--mono:"JetBrains Mono","Consolas","Courier New",monospace;
```

### 为什么不能用 kami 原版的字体栈

kami 原版写的是 `"Source Han Serif SC","Noto Serif CJK SC","Songti SC",Georgia,serif`。在这类 Windows 机器上，**这几个家族名都没装**，Chrome 会回退到内置 CJK 字体，其 ToUnicode 映射把常用字指向**康熙部首码位**：

| 字 | 错误码位 | 渲染 | 复制出来 |
|---|---|---|---|
| 用 | U+2F65 | 用 | ⽤ |
| 目 | U+2F6C | 目 | ⽬ |
| 方 | U+2F45 | 方 | ⽅ |
| 一 | U+2F00 | 一 | ⼀ |

**PDF 看着完全正常，但复制出来的文字全是错字。**这是本 skill 最容易复发的问题。

### 实测结论（本机）

| 字体 | 文本层 |
|---|---|
| STSong、STZhongsong、SimSun、KaiTi、FangSong、STKaiti、SimHei、Microsoft YaHei | 干净 |
| Source Han Serif SC、Noto Serif SC、Noto Sans SC、Songti SC、通用 `serif`、`sans-serif` | **错字** |

所以：**`font-family` 首位必须写本机确定存在的字体**。`serif` / `sans-serif` 这种通用关键字在中文场景下是危险写法。

### 用中宋替代 500 字重

kami 要求标题 500、正文 400，但宋体家族没有 500。设 `font-weight:500` 只会触发合成粗体（kami 明令禁止）。

解法：**标题换用华文中宋 `STZhongsong`**——它本身就是比宋体重一档的真字面，视觉上等价于 500，且不需要合成。同理，正文里的 `strong` 也改成"换中宋 + `font-weight:400`"，而不是加粗。

### SVG 里的文字同样会中招

`<text font-family="sans-serif">` 一样会落到那个坏字体。模板里已用 CSS 强制覆盖：

```css
.fig svg text{ font-family:var(--serif); }
```

自己新增 SVG 时，**不要依赖 `font-family` presentation 属性**，让 CSS 管。

## 四、字号阶梯（A4 印刷，单位 pt）

| 角色 | 字号 | 字体 | 行高 | 用在哪 |
|---|---|---|---|---|
| 封面主标题 | 34 | 中宋 | 1.16 | 封面 |
| 章标题 H1 | 22 | 中宋 | 1.20 | 五个部分 |
| 节标题 H2 | 16 | 中宋 | 1.25 | 1.1、4.1 这类 |
| 小标题 H3 | 13 | 中宋 | 1.30 | 它回答的问题 |
| 导语 | 11 | 宋 | 1.55 | 章首 ch-lead |
| 正文 | 10.5 | 宋 | 1.55 | 段落 |
| 表格 | 9.5 | 宋 | 1.45 | 普通表 |
| 紧凑表 | 8.5 | 宋 | 1.40 | 5 列以上 |
| 图注 / 页脚 | 9 | 宋 | 1.45 | fig-cap、footer |
| 标签 | 9 | 中宋 | 1.35 | 因果链标签、术语条目字段名 |

**阶梯纪律**：字号只能落在上表的档位上，不要出现 12.5 / 13.5 / 17.5 这种中间值。读者分辨不出 13.5 和 14，差异只会变成噪声。

## 五、间距节奏

基准 4pt：

| 档 | 值 | 用途 |
|---|---|---|
| xs | 2–3pt | 行内相邻 |
| sm | 4–5pt | 标签内边距 |
| md | 8–10pt | 组件内部 |
| lg | 16–20pt | 组件之间 |
| xl | 24–32pt | 节标题外边距 |
| 2xl | 40–60pt | 大节之间 |

**邻近律（标题属于它下面的内容）**：标题**下方**的间距必须明显小于**上方**，最好差 2 倍以上。模板里 `h2{margin:24pt 0 10pt}` 就是这个比例。反过来写（下宽上紧），标题会被读成上一节的尾巴，字号再大也救不回来。

**页边距**：`20mm 22mm 22mm 22mm`。比简历宽松，比正式信函紧凑，适合长文档阅读。

## 六、组件

### 没有提示框

**全书不使用任何带底色的提示框、强调边、图标框。** 五种内容性质（定义／原理／论文实例／易错／因果链）不再靠容器区分，改由**措辞**承担：

| 内容性质 | 承载方式 |
|---|---|
| 定义 | 普通段落，术语名用中宋，定义以“××是指……”开头 |
| 原理 | 普通段落，用“因为……所以……”显式写因果 |
| 论文实例 | 普通段落，句末带 `（Fig. 3）` 这类出处 |
| 易错／口径 | 普通段落，以「注意」二字起头，二字用赭 `#8b4513`，无底色 |
| 因果链 | 唯一保留的结构件：编号列表，无底色无边框 |

理由：一页里出现三种以上底色块，读者会先去分辨“这框是什么级别”，而不是读内容。判断信息的重要性应由文字本身承担，不该交给色块。

### 因果链

全书唯一的强调结构：

```css
.chain{ margin:14pt 0; page-break-inside:avoid; }
.chain-h{ font-size:9pt; color:var(--brand); letter-spacing:.9pt; }
.chain ol{ list-style:none; counter-reset:step; }
.chain li{ padding-left:17pt; position:relative; }
.chain li::before{ counter-increment:step; content:counter(step); color:var(--brand); }
```

- 标签 9pt 墨蓝，字距 0.9pt
- 编号用 `counter`，不手写，避免插入一条后全篇要改
- 无底色、无描边、无竖线。缩进与编号已足够与正文区分

### 「注意」段落

```css
.flag{ font-size:9.5pt; color:var(--olive); margin:9pt 0; }
.flag b{ font-family:var(--serif-med); color:var(--breaking-fg); margin-right:4pt; }
```

只给「注意」两个字上色，正文仍是常规墨色。这是全篇唯一允许出现的第二色相，且**只用于两个字**，不做底色、不做边框。

### 表格

只用水平细线，**无底色表头、无竖线、无外框**：

- 表头下边线 `0.6pt`，行分隔线 `0.25pt`，末行下边线 `0.6pt`
- 表头用中宋（不是加粗），颜色 `--dark-warm`
- 行高靠留白撑开，不靠线的粗细
- 5 列以上或 8 行以上加 `.compact`（8.5pt）
- 数值列加 `.financial`（右对齐 + `tabular-nums`）
- **不要**给数值上色，不要给表头上底色

### 图

- 内嵌 SVG，不用外部图片（避免字体/路径丢失）
- 描边 `--brand` 0.9pt，填充 `--brand-tint` / `--ivory`，轴线 `--border` 0.6pt，文字 `--dark-warm`
- 图题 9pt、`--stone`、居中；编号用中宋
- 图题要写"这张图要证明什么"，不是复述图里有什么

### 目录

- 条目 `padding:6pt 0` + 下边框 `0.3pt dotted`
- 页码墨蓝、中宋、右对齐、`tabular-nums`
- 不用手画引导点，引导线由条目下边框承担
- **与前言同页**：前言只有一段导语加一张表，独占一页会留下大半页空白。目录标题上方留 34pt 与前文拉开，两块的层级靠字号差（都是 22pt 中宋）和间距承担
- 目录项固定 7 条（五个部分 + 两个附录），加章节时记得同步 `pmark` 与 `data-toc-key`

### 封面

- `min-height:246mm` + `space-between`：上部眉标/标题/副标题，下部元信息
- 眉标 9pt 墨蓝、字距 1.6pt、大写
- **不画装饰性短横线**（kami 明令禁止 "short cover rules"）

## 七、禁止清单

写模板时逐条对照：

- [ ] 没有左侧竖线（`border-left` 做强调）
- [ ] 没有装饰性短横线（封面短横、标题下短横）
- [ ] 没有标题旁的竖条
- [ ] 没有 `font-style: italic`
- [ ] 没有 `font-weight:600` / `700` / `900`
- [ ] 没有纯白背景、没有冷灰
- [ ] 没有第二种彩色强调（绿/紫/青都不行）
- [ ] 没有 `rgba()` 背景
- [ ] 没有带底色的提示框、图标框、强调边
- [ ] 没有表格外框、竖线、表头底色
- [ ] 没有阴影

**删除测试**：一条线如果能删掉而不损失含义、状态、分组或导航，就删掉，用留白补上那个停顿。

## 八、Chrome 与 WeasyPrint 的差异（移植时必读）

kami 用 WeasyPrint 渲染，有几个能力 Chrome 没有。本 skill 的替代方案：

| WeasyPrint 能力 | Chrome | 本 skill 的做法 |
|---|---|---|
| `target-counter()` 自动目录页码 | 不支持 | `build_pdf.py` **两轮渲染**：学习轮定位章节页 → 产出轮（回填页码 + 剥离标记，合并为一次渲染）。目录项数超容量时才加修正轮 |
| `string-set` 页眉（当前章节名） | 不支持 | 暂不做页眉；页脚用「页码 · 书名」 |
| `@page { background }` 整页底色 | **不支持** | Chrome 只把背景铺到内容框，四周留白。改为 pypdf `merge_page(over=False)` 垫一整页底色 |
| `@page` 边距盒（`@top-right` 等） | 不支持 | 页脚用 reportlab 叠加；需要中文字体时注册 `STSONG.TTF` |
| `break-inside: avoid` | 支持 | 直接用 |

**因此 build_pdf.py 必须传 `--page-bg`（默认已开），verify_pdf.py 必须跑 `--check-bg`**，否则会得到四周白边的成品。

## 九、交付前自检

```bash
python scripts/build_pdf.py --html book.html --out book.pdf \
       --title "<书名>" --footer-title "<书名>"
python scripts/verify_pdf.py book.pdf --check-bg --render 1,2,3,5
```

然后**必须真的看图**，逐项确认：

1. 四角是羊皮纸色，不是白（`--check-bg` 已自动查）
2. 中文字符占比 > 10%，且无康熙部首告警（字体陷阱）
3. 目录页码与实际章起始页逐条一致
4. 全篇没有任何带底色的提示框、强调边、图标框（只允许编号因果链）
5. 表格没有表头底色、没有竖线
6. 没有一页只剩一两行（孤行），必要时调间距或删减前言内容
